# AlgoHar V2 — growth playbook

## Principle

Every algorithm is both product content and a distribution asset. The growth system should turn one verified lesson into multiple useful public artifacts without generating spam.

## Content atom

For each new lesson create from the same source:

- indexable `/course/<slug>` page;
- 20-45 second vertical clip showing the key state transition;
- one static carousel/diagram explaining the invariant;
- one short founder explanation with a link to the free demo;
- one practice prompt once the exercise engine exists.

Do not publish automatically to personal accounts without owner approval. Automation may prepare drafts, clips, metadata, UTMs and a publishing queue.

## Channels in order

1. Intent SEO: Russian queries like "бинарный поиск визуализация", "дерево отрезков как работает", "алгоритм Дейкстры визуализация".
2. Founder content: Telegram/VK/YouTube Shorts/Reels where the founder actually owns the account.
3. Student communities and university groups with administrator/community permission.
4. Creator/teacher referrals: tracked links and rev-share only after payments are verified.
5. Paid search: only after organic conversion establishes an acceptable CAC ceiling.

## SEO loop

Each lesson page must have:

- unique title and description;
- plain-language explanation before code;
- complexity terms in text;
- accessible crawlable copy around the interactive client component;
- internal links to prerequisite and next lessons;
- sitemap entry;
- no index bloat from empty/placeholder routes.

## Referral hypothesis

Once accounts exist, award a non-cash course benefit (for example a practice pack) for a verified referred activation. Do not implement cash payouts before legal/accounting handling is defined.

## Automation contract

Safe to automate:

- detect missing lesson metadata;
- generate content-draft queues from verified lesson facts;
- generate UTM links;
- report funnel gaps and broken routes;
- produce weekly aggregate KPI readout;
- propose the next lesson based on search demand and curriculum gaps.

Requires owner approval:

- publishing on personal/social accounts;
- sending outbound messages;
- changing prices;
- buying ads;
- issuing refunds or financial actions;
- making outcome claims.

## Weekly operating review

Report only source-backed values:

- attributed sessions by lesson/channel;
- unique algorithm opens;
- visualization completion rate;
- second-lesson rate;
- pricing views;
- verified checkout clicks and payments;
- seven-day retained learners;
- support defects and visualization correctness bugs.

Then choose one bottleneck for the next week. Avoid optimizing impressions if activation is broken.
